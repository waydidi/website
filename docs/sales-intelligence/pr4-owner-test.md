# Sales Intelligence PR 4 test guide

WhatsApp attachments require a funded model API, the configured WhatsApp access token with permission to retrieve media for the number, and a private file store. The existing `DB` binding is sufficient when migration `0047_stored_file_parts.sql` is applied. To use R2 instead, create a private bucket, set `R2_BUCKET_NAME` to its name in the Worker build variables, rebuild, and verify the deployed Worker has an R2 binding named `BUCKET`. When neither storage path is ready, attachments are treated as unreadable and the reason appears in AI Activity.

Use the existing Meta WhatsApp test number and a test environment approved by the owner. Keep `SALES_AI_MEDIA` off in production while reviewing. Enable `SALES_AI_MEDIA=1` and `SALES_AI_QUOTE_APPROVAL=whatsapp` in the test environment. The owner must have an active owner staff account linked to their Telegram account.

1. Send a synthetic flight screenshot and a synthetic itinerary PDF. Check that the assistant uses the trip details and asks you to confirm them. A synthetic transfer slip should never mark anything paid. Try a screenshot over 5 MiB or a PDF over 8 MiB. The assistant should ask you to type the details if it cannot read the file.
2. Ask for two simple transfers on different future dates. Check that there is one English approval card with two route lines and website prices. Edit one price and try its old approval button. Approve using the current card. Open only one of the links and accept it. Check that the other leg can still be accepted separately. In a second test quote, edit a leg in CRM and check that a link for another unaccepted leg from the earlier quote shows it is unavailable.
3. Try a child seat and an oversized bag or wheelchair. Check that the card shows the existing child-seat add-on and requires an owner-entered price and a fit check for unsupported equipment. Accept the quote and verify the child-seat count is prefilled and fixed as an existing priced add-on on the booking form. One request applies the same child-seat count to every leg in the quote. An hourly-hire request should go to staff.
4. Ask for a multi-day sightseeing itinerary. Open **Review itinerary draft** from the Telegram card. Check the grouped days and stops already saved in the existing trip builder. Check that the draft is unpriced and unpublished and only the owner can publish it.
5. Disable `SALES_AI_MEDIA` to turn the new intake and draft tools off again. Existing issued quotes retain their normal expiry and revision checks.

Raw supported files are private and purged with the existing AI activity retention period (180 days by default). Use synthetic files without personal details in tests.

## Production media checklist (instructions only; not executed)

1. Check whether `stored_file_parts` already exists in the live `DB` database. Without `BUCKET`, `putFile()` stores private files there in roughly 900 KB pieces. R2 is optional. The table is from migration `0047_stored_file_parts.sql`; its live presence has not been verified. This change probes the schema and logs a skipped attachment before any download or model call when neither storage path is configured.
2. If choosing R2, create a private bucket. Suggested new name: `waydidi-private-files` (availability has not been checked). Keep public access disabled. In Worker `waydidi-website` → Settings → Build → Build variables and secrets, set `R2_BUCKET_NAME=waydidi-private-files`, or the actual bucket name selected. Rebuild the approved commit: `vite.config.ts` generates an R2 binding named **`BUCKET`** from that build variable. Verify that binding on the deployed Worker. A runtime-only `R2_BUCKET_NAME` does not configure this build. No R2 API key is needed by application code using the binding.
3. Verify the existing runtime secret `WHATSAPP_TOKEN` is valid for the number/account and has `whatsapp_business_messaging` permission. The same bearer token retrieves the media URL and downloads its bytes; there is no separate media token in this code. Keep the existing phone-number ID, webhook app secret, verification token and message subscription working. No payment/slip permission or new message template is needed for reading a customer's attachment.
4. Verify `ANTHROPIC_API_KEY` has credit and the configured fast model supports images/PDFs. Then, after the owner-approved merge, enable runtime `SALES_AI_MEDIA=1` and list `whatsapp` in `SALES_AI_QUOTE_APPROVAL`. Existing assistant kill switches, pause and takeover still apply.
5. Use the test number with synthetic JPEG/PNG/WebP and PDF files; check AI Activity for successful extraction or an explicit storage/authentication/type/size failure. Images are capped at 5 MiB and PDFs at 8 MiB. Check that a transfer-slip image never changes payment state. Disable `SALES_AI_MEDIA` to stop the feature.

Sources: [Cloudflare build settings](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/), [R2 bindings](https://developers.cloudflare.com/r2/api/workers/workers-api-usage/), [Meta media download requirements](https://www.postman.com/meta/whatsapp-business-platform/request/zsq66eh/download-media).

## Fixed replies test

Enable runtime `ASSISTANT_FIXED_REPLIES=1` only after approval. Ask standalone contact/payment questions in English, Thai and Chinese. Each answer should have a zero-cost `fixed_reply` entry in AI Activity. Ask a mixed question (for example, “How do I pay? Also need a ride to Pattaya.”): it must use the existing AI flow. For hours, add only verified customer-ready FAQ text using the language-specific titles documented in README; without that note the question uses the AI flow. Repeat after taking over or pausing the chat, and with the global or channel switch off: no assistant reply should be sent. These fixed answers use the existing five-second batching.
